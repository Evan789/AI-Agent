# 通用 AI Agent 怎么做

日期：2026-10-09

目标产品是一个能下载安装的通用 Agent：自己的窗口里有对话和终端，模型只用 DeepSeek。它不替代旁边的大气诊断助手。

当前交付的是**本地初始版**：这台电脑上打开窗口就能对话。介绍页、安装包、账号、自动更新先不做。

## 先定下来的假设

下面这些如果和你的想法不一致，后面的做法要改。

- 程序名用 **YXBot**。安装目录、可执行文件、签名证书上的软件名、更新清单都写这个名字：`C:\Program Files\YXBot`、`YXBot.exe`、`%APPDATA%\YXBot\`。介绍页可以继续用中文产品名。
- 第一版在一台电脑上给一个已登录用户用。模型调用、对话和厂商 Key 都在这台电脑上。账号服务只负责注册、登录和令牌，不保存对话，也不保存 Key。
- 注册不对公网开放。初始白名单只有三个登录名：Evan、Sarah、Angela。三人只凭登录名和密码进入，不填邮箱，密码记在本机 `bootstrap-users.local`，不进仓库。这三人忘记密码时由管理员重置。以后加人仍走一次性邀请码，用完即失效。没有邀请码、也不在白名单里的人不能建号。
- 「通用」指换任务，不指换模型厂商，也不指内置大气、政务、代码等行业包。第一版只接 DeepSeek，默认用 `AI Agent/.env` 里现有的内网网关。不通义、智谱、Kimi、豆包、硅基流动。行业能力以后用工具接，不写进第一版。
- 界面是独立窗口：上面对话，下面本机终端。不做 VS Code 插件，也不把产品做成网站。
- 第一版只做 Windows。你现在的环境就是 Windows，安装包、签名、杀毒误报都先在这一边踩完。
- DeepSeek 的 Key 放在用户自己的电脑上。安装包、介绍页、账号数据库里都不带这把 Key。
- 账号和自动更新仍按原计划保留，但本地初始版先不做。初始版没有登录。三人白名单留到账号那一步再用。

## 这个产品和 harness 是什么关系

Claude Code、Cline、OpenCode、WorkBuddy 客户端这一类，卖的不是模型，是包在模型外面的那一层：对话界面、工具、权限、上下文、安装方式。模型可以换。这一层通常就叫 harness。

所以这个产品要自己做的是这些事：

1. 窗口：对话，加上能看见命令输出的终端。
2. 循环：模型决定下一步，程序执行工具，把结果喂回去，直到它给出最终答复或用户停下。
3. 模型：只接 DeepSeek。地址、模型名、Key、Host 可以改，用来对准现有内网网关。
4. 分发：一个介绍页，上面有 Windows 安装包，装上之后能自己更新。
5. 账号：打开客户端要先登录。服务端只认人，不跑模型。

模型训练、计费、插件市场、对话上云都不在第一版。

## 和现有代码的关系

`AI Agent/proto` 里已有 `run_loop` 和 `ToolBus`，`aq-assistant` 用它们做大气诊断。那个循环的上下文预算大约 4000 字，决策是「调工具 / 结束 / 追问」三种，工具是分析器，不是读写文件和跑命令。

通用产品不要从改 `aq-assistant` 开始。诊断助手的规则和会话会缠进来。新目录单独做。DeepSeek 仍走现有内网网关的聊天补全协议，不复用诊断助手那套 JSON 决策格式。

## 三条路线

**套一个开源 harness，换上 DeepSeek 和皮肤。**  
OpenCode、Cline 这一类已经有循环、工具和界面。接上现有 DeepSeek 网关，再做一个下载页，最快能给别人用。代价是界面、升级和许可证都受上游约束，以后想改权限或终端，经常是在跟别人的架构打架。

**自己做一薄层，只覆盖对话、终端、DeepSeek 和安装。**  
第一版功能少，但是窗口、循环、Key 和安装包都是自己的。后面加工具不会先征得上游同意。这是建议走的路。

**做成网站，打开网页就能用。**  
介绍和产品在一起，省掉安装包。本机终端和读写用户文件会很难做：浏览器拿不到对方电脑上的 shell。和「下载安装、自己的终端」不一致。

## 建议的结构

```text
介绍页（静态页面）──── 下载 Windows 安装包
                              │
账号服务（长期在线）◀── 注册 / 登录 / 刷新令牌
                              │
                         桌面窗口
                         ├─ 登录
                         ├─ 对话
                         ├─ 终端（本机 shell 的输出）
                         └─ 设置（DeepSeek 地址、模型、Key、Host）
                              │
                         本机上的 Agent 进程
                         ├─ DeepSeek 聊天补全
                         ├─ 循环：模型 → 工具 → 结果 → 再问模型
                         └─ 权限：写文件、跑命令之前先问用户

版本清单（对象存储上的一个文件）◀── 启动时检查，有新版本再下载已签名安装包
```

介绍页、账号服务、版本清单分成三处。介绍页挂了，已经登录的客户端还能用。账号服务停了，未过期的登录令牌仍然有效，本机对话继续；令牌过期后要等服务恢复才能再登录。版本清单挂了，就跳过这次更新，不挡住打开程序。

密钥、对话记录、允许过的命令、登录令牌，都放在用户目录 `%APPDATA%\YXBot\`。不要放在安装目录，升级时才不会被覆盖。

## DeepSeek 怎么接

第一版只有 DeepSeek。协议用现有内网网关的聊天补全，默认值来自 `AI Agent/.env`：地址、模型名、Key、Host。设置里这四项可以改，用来跟着网关调整，不是用来换别的厂商。

工具调用只认一个子集：非流式、`tools` 里只有函数调用、只读 `tool_calls`。网关暂时不支持时，对话仍可纯聊天，设置页写明原因。流式输出以后再做。

Key 只存在本机。介绍页、安装包、日志里都不出现。日志要打码，避免请求体被完整写进文件。

## 界面里有什么

窗口里这些部分：

- 登录：没有有效令牌时先看到登录。Evan、Sarah、Angela 只填登录名和密码。不在白名单里的人要注册，才同时填写邮箱、邀请码和密码；邀请码无效就停在这一页。
- 对话：用户输入，模型回复，中间能看到它调用了哪个工具、结果是什么。
- 终端：展示本机命令和输出。命令由模型提出，用户点允许后才执行。终端不是再给用户一个空白 PowerShell 就算完成，而是让人看见 Agent 正在跑什么。
- 设置：填 DeepSeek 的地址、模型、Key、Host，并测试连通。测试只发一句最短请求，成功或失败直接写在设置页上。
- 关于：当前版本；发现新版本时显示进度，替换失败时说明仍在使用旧版本。

工作目录在窗口里选一个文件夹。读文件、改文件、跑命令都限制在这个目录下面。跳出这个目录要再问一次。

第一版工具只有四个：列出目录、读文件、写文件、在工作目录里执行命令。搜索、网页、浏览器、长期记忆都先不做。

写文件和执行命令默认每次确认。用户可以对「这一会话允许该命令」点一次记住，关掉窗口就失效。不要做「永远允许所有命令」。

## 介绍页和安装

介绍页是静态页，放这几样：产品是做什么的、一张窗口截图、Windows 版本要求、下载按钮、DeepSeek Key 由单位配置在本机的说明。页面写明需要单位邀请码才能注册。注册表单在客户端里，不在网页上开放。

下载按钮指向安装包的固定地址。国内用户下 GitHub Release 经常很慢，安装包放到国内对象存储（阿里云 OSS 或腾讯云 COS），介绍页可以放在同一套存储的静态网站上，也可以是一台只托管页面的服务器。页面和安装包分离：换安装包只改链接或覆盖文件，不必改页面逻辑。

Windows 安装用安装程序：选安装位置、开始菜单快捷方式、卸载入口。桌面壳用 Tauri，安装包体积小，并且自带更新机制。Electron 能更快找到现成界面写法，体积大一截。不用 PyInstaller 打一个只有命令行的 exe 再假装是产品界面。

自动更新要验签名，所以第一版就买 Windows 代码签名证书。客户端启动时读取对象存储上的版本清单，版本更高才下载。新包下完后等用户重启再替换。签名对不上、下载中断、替换失败，都留在旧版本并在「关于」里写明原因。更新通道不经过账号服务，避免登录故障挡住升级。

账号服务单独部署，用 HTTPS。库存用户标识、密码哈希、令牌、过期时间，以及邀请码和它是否已使用。密码只存哈希。上线时用白名单建好 Evan、Sarah、Angela 三个账号，只有登录名和密码哈希，没有邮箱。明文密码只存在本机 `bootstrap-users.local`。邀请码由服务器上的管理员命令生成，第一版不做邀请管理网页。以后的人注册时核销邀请码，并填写邮箱；邮箱验证码只用于这些后加的人找回密码。白名单三人忘记密码时，管理员在服务器上改哈希。令牌有效期 14 天，客户端在过期前用刷新接口续期。退出登录时本机删掉令牌。卸载程序时，账号仍留在服务器上，本机配置按用户是否勾选一并删除。

## 本地初始版怎么运行

这台电脑上依赖已经装过。以后只要：

```text
python -m yxbot
```

浏览器打开 http://127.0.0.1:8766/ 。

换一台没装过的电脑，才需要先在 `通用AI Agent构建` 目录执行一次 `pip install -e .`。虚拟环境可以不建。

浏览器打开 http://127.0.0.1:8766/ 。DeepSeek 使用上级目录 `AI Agent/.env`。需要能访问 `ds.local.ai`（VPN，或先运行仓库根目录的 `setup_ds_hosts.ps1`）。

窗口里可以对话、指定工作目录、看终端输出。读取目录和文件会直接执行。写入文件和运行命令会先停住，等页面上点允许或拒绝。模型调用和工具是同一条 `loop.py`，页面不再自己开一个 shell。

## 按这个顺序做

第 1、2 步是本地初始版。第 3、4、5 步先不做。

**1. 命令行把循环跑通**  
在一个文件夹里，用现有内网 DeepSeek 网关完成：读一个文件、改一个文件、跑一条命令。命令执行前在终端里问 `y/n`。Key 放本机配置文件。  
验收：断网时给出明确失败；Key 错误时不重试死循环；工具结果写回对话后模型能收尾。

**2. 做窗口**  
对话、终端输出、设置、选择工作目录。终端里看到的命令和命令行版是同一套执行路径，不能在界面里再写一个 shell。  
验收：不看命令行，只靠窗口完成第 1 步的三个动作。

**3. 做介绍页和安装包（暂缓）**  
一台没装过开发环境的 Windows，从页面下载，安装，打开，填自己的 Key，跑通第 1 步。这一步先不拦登录。  
验收：安装包里搜不到 Key；卸载后程序文件删除，`%APPDATA%\YXBot\` 还在，除非用户勾选一并删除。

**4. 做账号（暂缓）**  
先导入白名单里的 Evan、Sarah、Angela。三人只提交登录名和密码就能登录，请求里不需要邮箱。管理员再生成邀请码，供以后的人用邮箱、邀请码和密码注册。未登录进不了对话。同一邀请码不能注册第二个账号。账号库里只有用户、令牌和邀请码，没有对话，没有 DeepSeek Key。  
验收：白名单账号不填邮箱也能登录；白名单以外且没有邀请码时注册失败；账号服务停机时，未过期令牌仍能打开本机对话；令牌过期后给出明确的登录失败，而不是空白窗口。

**5. 做自动更新（暂缓）**  
用已签名的安装包发布一个更高版本。旧客户端启动后能发现、下载，重启后变成新版本。  
验收：清单被篡改或签名不对时拒绝安装，当前版本仍可使用；更新过程中不删除 `%APPDATA%\YXBot\`。

本地初始版做到第 2 步即可交付。第 3、4、5 步以后再做。不要加对话上云、插件、其他模型厂商。记忆仍然不做。

## 风险

- 内网网关的工具调用字段若和公开的 DeepSeek 接口不一致，以这台网关的实际返回为准，只解析 `tool_calls`。
- 模型可以提议删除文件或格式化一类命令。工作目录限制和执行前确认是第一版的安全边界，不是提示词。
- 自动更新一旦上线，签名私钥和版本清单的写权限就是发布通道本身。私钥不进仓库，清单所在的存储桶和介绍页的读权限分开。
- 账号服务要备份数据库，并限制登录失败的频率，避免被人拿登录名撞密码。后加用户的邮箱验证码同样要限频率。
- 内网网关要带特定 Host。设置里「连接地址」和「Host 头」分开，否则 `ds.local.ai` 只能在能解析该域名的机器上用。
