# 通用 AI Agent 怎么做

日期：2026-10-09

这是一份构建说明，不是实现。目标产品是一个能下载安装的通用 Agent：自己的窗口里有对话和终端，模型从大陆能直接调用的主流厂商里选。它不替代旁边的大气诊断助手。

## 先定下来的假设

下面这些如果和你的想法不一致，后面的做法要改。

- 程序名用 **YXBot**。安装目录、可执行文件、签名证书上的软件名、更新清单都写这个名字：`C:\Program Files\YXBot`、`YXBot.exe`、`%APPDATA%\YXBot\`。介绍页可以继续用中文产品名。
- 第一版在一台电脑上给一个已登录用户用。模型调用、对话和厂商 Key 都在这台电脑上。账号服务只负责注册、登录和令牌，不保存对话，也不保存 Key。
- 注册不对公网开放。初始白名单只有三个登录名：Evan、Sarah、Angela，密码记在本机 `bootstrap-users.local`，不进仓库。以后加人仍走一次性邀请码，用完即失效。没有邀请码、也不在白名单里的人不能建号。
- 「通用」指换任务、换模型，不指内置大气、政务、代码等行业包。行业能力以后用工具接，不写进第一版。
- 界面是独立窗口：上面对话，下面本机终端。不做 VS Code 插件，也不把产品做成网站。
- 第一版只做 Windows。你现在的环境就是 Windows，安装包、签名、杀毒误报都先在这一边踩完。
- 密钥放在用户自己的电脑上。安装包、介绍页、账号数据库里都不带厂商 Key。
- 第一版包含账号和自动更新。账号做到凭邀请码注册、登录、退出、找回密码。自动更新做到启动时检查版本、下载已签名的新包、重启后替换，失败则继续用旧版本。对话跨设备同步不在第一版。

## 这个产品和 harness 是什么关系

Claude Code、Cline、OpenCode、WorkBuddy 客户端这一类，卖的不是模型，是包在模型外面的那一层：对话界面、工具、权限、上下文、安装方式。模型可以换。这一层通常就叫 harness。

所以这个产品要自己做的是四件事：

1. 窗口：对话，加上能看见命令输出的终端。
2. 循环：模型决定下一步，程序执行工具，把结果喂回去，直到它给出最终答复或用户停下。
3. 厂商：同一套调用方式，换成不同公司的地址、模型和 Key。
4. 分发：一个介绍页，上面有 Windows 安装包，装上之后能自己更新。
5. 账号：打开客户端要先登录。服务端只认人，不跑模型。

模型训练、计费、插件市场、对话上云都不在第一版。

## 和现有代码的关系

`AI Agent/proto` 里已有 `run_loop` 和 `ToolBus`，`aq-assistant` 用它们做大气诊断。那个循环的上下文预算大约 4000 字，决策是「调工具 / 结束 / 追问」三种，工具是分析器，不是读写文件和跑命令。

通用产品不要从改 `aq-assistant` 开始。诊断助手的规则、会话和 DeepSeek 内网地址会缠进来。新目录单独做。可以借鉴的只有两点：网关按角色调用模型，以及工具调用和最终答复分开。厂商协议直接按各家的 OpenAI 兼容接口写，不复用诊断助手那套 JSON 决策格式。

## 三条路线

**套一个开源 harness，换国内厂商和皮肤。**  
OpenCode、Cline 这一类已经有循环、工具和界面。接上 DeepSeek、通义，再做一个下载页，最快能给别人用。代价是界面、升级和许可证都受上游约束，以后想改权限或终端，经常是在跟别人的架构打架。

**自己做一薄层，只覆盖对话、终端、厂商和安装。**  
第一版功能少，但是窗口、循环、Key 和安装包都是自己的。后面加工具不会先征得上游同意。这是建议走的路。

**做成网站，打开网页就能用。**  
介绍和产品在一起，省掉安装包。本机终端和读写用户文件会很难做：浏览器拿不到对方电脑上的 shell。和「下载安装、自己的终端」不一致。

## 建议的结构

```text
介绍页（静态页面）──── 下载 Windows 安装包
                              │
账号服务（长期在线）◀── 注册 / 登录 / 刷新令牌
                              │
                         桌面窗口
                         ├─ 登录
                         ├─ 对话
                         ├─ 终端（本机 shell 的输出）
                         └─ 设置（厂商、模型、Key、自定义地址）
                              │
                         本机上的 Agent 进程
                         ├─ 厂商适配：统一走聊天补全
                         ├─ 循环：模型 → 工具 → 结果 → 再问模型
                         └─ 权限：写文件、跑命令之前先问用户

版本清单（对象存储上的一个文件）◀── 启动时检查，有新版本再下载已签名安装包
```

介绍页、账号服务、版本清单分成三处。介绍页挂了，已经登录的客户端还能用。账号服务停了，未过期的登录令牌仍然有效，本机对话继续；令牌过期后要等服务恢复才能再登录。版本清单挂了，就跳过这次更新，不挡住打开程序。

密钥、对话记录、允许过的命令、登录令牌，都放在用户目录 `%APPDATA%\YXBot\`。不要放在安装目录，升级时才不会被覆盖。

## 厂商怎么接

大陆主流厂商里，能直接拿来做第一版的，多数都提供 OpenAI 风格的 `chat/completions`。客户端只维护这一种协议，每个厂商是一条预置：显示名、基础地址、默认模型、Key 的申请入口。用户还能填自定义地址，用来接你们现在的 `ds.local.ai` 网关，或以后别的中转。

第一版预置这些（地址以动手时的官方文档为准）：

| 厂商 | 用途 |
| --- | --- |
| DeepSeek | 默认推荐。官方接口在国内可直接用，工具调用比较稳 |
| 阿里云百炼（通义千问） | 兼容模式 |
| 智谱 GLM | 开放平台 |
| 月之暗面 Kimi | 开放平台 |
| 火山方舟（豆包） | 模型名常常是接入点 ID，设置里要允许手填 |
| 硅基流动 | 一个 Key 能换多家开源模型，适合做「先跑通」 |
| 自定义 | 基础地址 + 模型名 + Key，覆盖内网网关 |

百度千帆、腾讯混元也能接，但兼容层更别扭，放第二版。OpenAI、Anthropic 不作为预置承诺，需要代理的人用自定义地址自己填。

工具调用是各家兼容接口里最容易分叉的地方。第一版不要为每家写一套解析。选一个最小子集：非流式、`tools` 里只有函数调用、只读 `tool_calls`。某家返回对不上，设置页标明「该厂商暂不支持工具」，对话仍可纯聊天。流式输出第二版再做。

Key 只存在本机。介绍页、安装包、日志里都不出现。日志要打码，避免请求体被完整写进文件。

## 界面里有什么

窗口里这些部分：

- 登录：没有有效令牌时先看到登录。注册要同时填写邮箱、邀请码和密码，邀请码无效就停在这一页。
- 对话：用户输入，模型回复，中间能看到它调用了哪个工具、结果是什么。
- 终端：展示本机命令和输出。命令由模型提出，用户点允许后才执行。终端不是再给用户一个空白 PowerShell 就算完成，而是让人看见 Agent 正在跑什么。
- 设置：选厂商、填 Key、选模型、测试连通。测试只发一句最短请求，成功或失败直接写在设置页上。
- 关于：当前版本；发现新版本时显示进度，替换失败时说明仍在使用旧版本。

工作目录在窗口里选一个文件夹。读文件、改文件、跑命令都限制在这个目录下面。跳出这个目录要再问一次。

第一版工具只有四个：列出目录、读文件、写文件、在工作目录里执行命令。搜索、网页、浏览器、长期记忆都先不做。

写文件和执行命令默认每次确认。用户可以对「这一会话允许该命令」点一次记住，关掉窗口就失效。不要做「永远允许所有命令」。

## 介绍页和安装

介绍页是静态页，放这几样：产品是做什么的、一张窗口截图、Windows 版本要求、下载按钮、Key 要用户自己去厂商申请的说明。页面写明需要单位邀请码才能注册。注册表单在客户端里，不在网页上开放。

下载按钮指向安装包的固定地址。国内用户下 GitHub Release 经常很慢，安装包放到国内对象存储（阿里云 OSS 或腾讯云 COS），介绍页可以放在同一套存储的静态网站上，也可以是一台只托管页面的服务器。页面和安装包分离：换安装包只改链接或覆盖文件，不必改页面逻辑。

Windows 安装用安装程序：选安装位置、开始菜单快捷方式、卸载入口。桌面壳用 Tauri，安装包体积小，并且自带更新机制。Electron 能更快找到现成界面写法，体积大一截。不用 PyInstaller 打一个只有命令行的 exe 再假装是产品界面。

自动更新要验签名，所以第一版就买 Windows 代码签名证书。客户端启动时读取对象存储上的版本清单，版本更高才下载。新包下完后等用户重启再替换。签名对不上、下载中断、替换失败，都留在旧版本并在「关于」里写明原因。更新通道不经过账号服务，避免登录故障挡住升级。

账号服务单独部署，用 HTTPS。库存用户标识、密码哈希、令牌、过期时间，以及邀请码和它是否已使用。密码只存哈希。上线时用白名单建好 Evan、Sarah、Angela 三个账号，明文密码只存在本机 `bootstrap-users.local`。邀请码由服务器上的管理员命令生成，第一版不做邀请管理网页。注册时核销邀请码；找回密码用邮箱验证码，且只发给已经注册的邮箱。令牌有效期 14 天，客户端在过期前用刷新接口续期。退出登录时本机删掉令牌。卸载程序时，账号仍留在服务器上，本机配置按用户是否勾选一并删除。

## 按这个顺序做

每一步做完要能演示，再做下一步。

**1. 命令行把循环跑通**  
在一个文件夹里，用 DeepSeek 官方接口完成：读一个文件、改一个文件、跑一条命令。命令执行前在终端里问 `y/n`。Key 放本机配置文件。  
验收：断网时给出明确失败；Key 错误时不重试死循环；工具结果写回对话后模型能收尾。

**2. 把厂商换成预置列表**  
同一条命令行，换成通义、智谱、Kimi、豆包、硅基流动和自定义地址。每家做一次「只聊天」和一次「读文件」。读文件失败的厂商，在列表里标成暂不支持工具。  
验收：换厂商不改循环代码，只改配置。

**3. 做窗口**  
对话、终端输出、设置、选择工作目录。终端里看到的命令和命令行版是同一套执行路径，不能在界面里再写一个 shell。  
验收：不看命令行，只靠窗口完成第 1 步的三个动作。

**4. 做介绍页和安装包**  
一台没装过开发环境的 Windows，从页面下载，安装，打开，填自己的 Key，跑通第 1 步。这一步先不拦登录。  
验收：安装包里搜不到 Key；卸载后程序文件删除，`%APPDATA%\YXBot\` 还在，除非用户勾选一并删除。

**5. 做账号**  
先导入白名单里的 Evan、Sarah、Angela，三人用登录名和密码直接登录。管理员再生成邀请码，供以后的人用邮箱、邀请码和密码注册。未登录进不了对话。同一邀请码不能注册第二个账号。账号库里只有用户、令牌和邀请码，没有对话，没有厂商 Key。  
验收：白名单以外且没有邀请码时注册失败；账号服务停机时，未过期令牌仍能打开本机对话；令牌过期后给出明确的登录失败，而不是空白窗口。

**6. 做自动更新**  
用已签名的安装包发布一个更高版本。旧客户端启动后能发现、下载，重启后变成新版本。  
验收：清单被篡改或签名不对时拒绝安装，当前版本仍可使用；更新过程中不删除 `%APPDATA%\YXBot\`。

第 6 步完成，才算这个产品的第一版。在那之前不要加对话上云、插件和市场。记忆仍然不做。

## 风险

- 厂商都说兼容 OpenAI，工具调用的字段仍会有差别。所以第 2 步要一家一家试，不能只试 DeepSeek。
- 模型可以提议删除文件或格式化一类命令。工作目录限制和执行前确认是第一版的安全边界，不是提示词。
- 自动更新一旦上线，签名私钥和版本清单的写权限就是发布通道本身。私钥不进仓库，清单所在的存储桶和介绍页的读权限分开。
- 账号服务要备份数据库，并限制登录和验证码的频率，避免被人拿来撞库或刷邮箱。
- 豆包的模型名经常是接入点 ID，和别家的 `deepseek-chat` 这种固定名字不一样。设置里模型名必须能手改。
- 内网网关要带特定 Host。自定义厂商里留一个「连接地址」和「Host 头」分开的选项，否则你们现有的 `ds.local.ai` 只能在能解析该域名的机器上用。
